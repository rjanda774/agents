# CLAUDE.md - AI Assistant Guide for This Repository

## Project Overview

**Master AI Agentic Engineering** - A 6-week educational course teaching autonomous AI agent development using multiple frameworks. Created by Ed Donner, MIT licensed. The repository contains lab notebooks, working examples, and community contributions from course participants.

This is **not** a library or production application. It is a collection of educational materials, Jupyter notebooks, and standalone scripts organized by weekly topics.

## Repository Structure

```
agents/
├── 1_foundations/          # Week 1: Agent fundamentals, tool use, message loops
├── 2_openai/               # Week 2: OpenAI Agents SDK, multi-agent research system
├── 3_crew/                 # Week 3: CrewAI framework (YAML-config, decorator-based crews)
├── 4_langgraph/            # Week 4: LangGraph state machines, sidekick assistant
├── 5_autogen/              # Week 5: Microsoft AutoGen, message-based agents
├── 6_mcp/                  # Week 6: Model Context Protocol, trading simulation
├── guides/                 # 12 educational Jupyter notebooks (Python, async, APIs, etc.)
├── setup/                  # Platform-specific setup instructions (Mac, PC, Linux, WSL)
├── assets/                 # Images for documentation
├── pyproject.toml          # Main project config (UV package manager)
├── requirements.txt        # Compiled dependency tree (auto-generated by uv)
├── uv.lock                 # Dependency lock file
├── .python-version         # Python 3.12
└── README.md               # Course overview and setup links
```

### Weekly Module Layout

Each week folder (`1_foundations/` through `6_mcp/`) typically contains:
- **Lab notebooks**: `1_lab1.ipynb` through `4_lab4.ipynb` (progressive difficulty)
- **Application scripts**: Standalone `.py` files (e.g., `app.py`, `sidekick.py`)
- **Community contributions**: `community_contributions/` subfolder with student projects

### CrewAI Projects (Week 3)

CrewAI projects under `3_crew/` have a distinct structure:
```
3_crew/<project_name>/
├── src/<project_name>/
│   ├── crew.py              # Crew definition (@agent, @task, @crew decorators)
│   ├── main.py              # Entry point
│   ├── config/
│   │   ├── agents.yaml      # Agent role/goal/backstory definitions
│   │   └── tasks.yaml       # Task descriptions and expected outputs
│   └── tools/               # Custom tool implementations
├── pyproject.toml           # Crew-specific dependencies
└── output/                  # Generated output files
```

## Build System & Dependencies

### Package Manager: UV

This project uses [UV](https://docs.astral.sh/uv/) for dependency management.

```bash
# Install all dependencies
uv sync

# Add a new dependency
uv add <package-name>

# Run a Python script
uv run python <script.py>

# Run a Jupyter notebook kernel
uv run jupyter lab
```

## Environment Variables

Projects expect API keys in `.env` files (gitignored). Common keys:
- `OPENAI_API_KEY` - Required for most labs
- `ANTHROPIC_API_KEY` - For Claude-based agents
- `GOOGLE_API_KEY` / `GEMINI_API_KEY` - For Gemini (CrewAI needs both)
- `POLYGON_API_KEY` - For stock market data (Week 6)
- `SENDGRID_API_KEY` - For email functionality (Week 2)
- `PUSHOVER_USER` / `PUSHOVER_TOKEN` - For push notifications (Week 1)

## Testing & Quality

- **No formal test suite** - This is an educational repository, not a production codebase
- **No CI/CD pipelines** configured
- **No linter/formatter** configured (no ruff, black, flake8, etc.)
- **No type checking** configured (no mypy, pyright)
- Code quality is maintained through PR-based community reviews (456+ merged PRs)

## Development Workflow

1. Run `uv sync` to install dependencies
2. Open the relevant week's lab notebooks (`.ipynb`) in Cursor/VS Code/Jupyter
3. Ensure `.env` file has required API keys
4. Run notebook cells progressively or execute scripts with `uv run python <file>`
5. For CrewAI: `cd 3_crew/<project>` then `crewai run`

## Conventions & Patterns

### Code Style
- No enforced style guide - code varies across contributors
- Most code uses standard Python conventions (PEP 8 loosely followed)
- Type hints used inconsistently (some files use Pydantic models, others don't)
- Docstrings are sparse; code is meant to be read alongside course videos

### Agent Architecture Patterns

1. **OpenAI Agents SDK** (Week 2): Structured agents with Pydantic output models, async execution, web search tools
2. **CrewAI** (Week 3): YAML-configured agents/tasks, decorator-based crews (`@agent`, `@task`, `@crew`), sequential/hierarchical processes
3. **LangGraph** (Week 4): `TypedDict` state, graph nodes, `MemorySaver` persistence, tool nodes
4. **AutoGen** (Week 5): `RoutedAgent` with message handlers, multi-agent conversations
5. **MCP** (Week 6): Tools exposed as MCP servers, agents as MCP clients, SQLite persistence

### File Naming
- Lab files: `1_lab1.ipynb`, `2_lab2.ipynb`, etc.
- App entry points: `app.py`
- Agent definitions: descriptive names (`sidekick.py`, `traders.py`, `research_manager.py`)

## Important Caveats

- `.env` files are gitignored and must be created locally with appropriate API keys
- Some projects depend on external services (OpenAI, Anthropic, Polygon, SendGrid) and will fail without valid API keys
- CrewAI on Windows requires Microsoft Build Tools (for Chroma dependency)
- The `3_crew/engineering_team/output/` directory is gitignored
- SQLite databases in `6_mcp/memory/` are gitignored
- Community contribution folders contain student code of varying quality and completeness
- Playwright requires browser installation: `playwright install`

## Git Workflow

- Repository uses GitHub PR flow
- Community contributions go in `<week>/community_contributions/` folders
- Main branch is `master`
